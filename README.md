# Lecture Assistant Bot

Telegram-бот на aiogram 3.22.0. Поддерживается Python 3.9+ (проверено на 3.9.6 и 3.12.16).
Зависимости не менялись: GigaChat вызывается асинхронно через имеющийся aiohttp.

## Настроенное окружение на этом Mac

Для подключения к GigaChat настроен Python 3.12 с OpenSSL в `.venv312`.
Базовый Python находится в `.python/`; обе папки локальные и исключены из Git.
Не удаляйте `.python/`, пока используете это окружение.
Старое окружение сохранено как `.venv39-backup`. Путь `.venv` теперь является
символической ссылкой на `.venv312`, поэтому прежний интерпретатор проекта
`.venv/bin/python` также запускает Python 3.12 с OpenSSL. Уже запущенные процессы
нужно остановить и запустить заново.

```sh
.venv312/bin/python -m app.main
```

В существующей конфигурации запуска PyCharm `main` указан `.venv312/bin/python`
и запуск модуля `app.main`. В `.env` задан корневой сертификат
`certs/russian_trusted_root_ca_pem.crt`; путь считается от корня проекта.

## Локальный запуск на Mac

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Заполните `.env`: `BOT_TOKEN`, `GIGACHAT_CREDENTIALS` (ключ авторизации,
не access token), `GIGACHAT_SCOPE=GIGACHAT_API_PERS`, `GIGACHAT_MODEL=GigaChat-2`.
При необходимости укажите `PROXY_URL` только для Telegram.

Установите доверенный корневой сертификат НУЦ Минцифры по
[официальной инструкции](https://developers.sber.ru/docs/ru/gigachat/certificates)
и укажите путь к PEM в `GIGACHAT_CA_BUNDLE_FILE`, например
`/Users/yourname/certs/russian_trusted_root_ca_pem.crt`.
Используйте сертификат из доверенного официального источника. Код дополняет
стандартное хранилище CA, проверка TLS всегда включена. Если сертификат уже
доступен стандартному SSL-контексту Python, переменная не обязательна.

```sh
python -m app.main
```

Первый запрос: `/start` → «Добавить файл» → отправьте небольшой TXT в UTF-8
или PDF → «Конспект» → «Краткая выжимка» под тем же файлом.
Нажатия расходуют токены API. Оба действия сохраняют текущую лекцию.
Конспект раскрывает темы, определения, объяснения, формулы и примеры из источника;
для большой содержательной лекции промпт ориентирует модель на 800–1600 слов.
Краткая выжимка — связный пересказ в пределах 7 тематических пунктов,
ориентировочно 250–450 слов. Это ориентиры, а не гарантированный объём:
короткий или неполный источник не должен раздуваться за счёт выдуманных деталей.
Лимит генерации: 6000 токенов для конспекта и 2400 для пересказа.
TXT также поддерживает Windows-1251. Для презентаций PPT и PPTX обе кнопки
отправляют файл во вложения GigaChat (как PDF). Для ODP бот извлекает текст
слайдов в исходном порядке локально; изображения и диаграммы ODP не анализируются.
Пустой или повреждённый ODP отклоняется с предложением пересохранить файл.
Вложения ограничены 40 МБ, XML-содержимое ODP — 16 МБ в распакованном виде.
Для ODT обе команды используют текст документа: заголовки, абзацы, списки и текст
таблиц. Изображения и формулы в виде объектов не распознаются. Повреждённые,
пустые и слишком большие ODT отклоняются с понятной ошибкой.
DOCX принимается, но ИИ для него пока недоступен. Результат длиннее 4096 UTF-16 единиц
возвращается файлом TXT. Очень большие лекции могут превысить контекст модели;
в этом случае бот предложит уменьшить файл, без молчаливого обрезания текста.

## Хранение и Amvera

Без `UPLOAD_DIR` файлы сохраняются в `<корень проекта>/files/`, независимо
от рабочей директории. Относительный `UPLOAD_DIR` также считается от корня
проекта. Структура: `<UPLOAD_DIR>/<telegram_user_id>/<uuid>.<расширение>`.
`.env` и `files/` исключены из Git.

На Amvera настройте запуск `python -m app.main` из корня проекта,
установку `pip install -r requirements.txt` и постоянное хранилище `/data`.
Используйте одну реплику бота. В переменных/секретах приложения задайте:

| Переменная | Mac | Amvera |
| --- | --- | --- |
| `BOT_TOKEN` | секрет в `.env` | секрет приложения |
| `GIGACHAT_CREDENTIALS` | секрет в `.env` | секрет приложения |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | `GIGACHAT_API_PERS` |
| `GIGACHAT_MODEL` | `GigaChat-2` | `GigaChat-2` |
| `GIGACHAT_CA_BUNDLE_FILE` | путь к доверенному PEM | например `/data/certs/russian_trusted_root_ca_pem.crt` |
| `UPLOAD_DIR` | не задана или свой путь | `/data/uploads` |
| `PROXY_URL` | при необходимости | при необходимости |
| `ADMIN_ID` | необязательно | необязательно |

Разместите доверенный PEM по указанному пути до запуска приложения.
Локальная папка и вложенные каталоги создаются автоматически. Новая лекция
заменяет предыдущую только после скачивания и отправки новых кнопок.
Предыдущий файл удаляется, а при активной генерации — после её завершения.
Отдельный счётчик защищает также файлы, ожидающие очередь запросов.

FSM находится в памяти процесса. После перезапуска старые кнопки не работают:
загрузите лекцию заново. Сохранившиеся на диске файлы от прошлых запусков
не восстанавливаются автоматически и могут потребовать ручной очистки.
FSM использует GLOBAL_USER: у пользователя одна текущая лекция во всех чатах.
Кнопки дополнительно проверяют чат и ID сообщения.

## Проверка

```sh
.venv/bin/python -B -m unittest discover -s tests -v
```

Тесты не обращаются к Telegram/GigaChat и не требуют ключей.
Проверяются загрузка, одинаковые имена, обе кнопки, старые кнопки,
потеря FSM, ошибка загрузки, замена во время генерации, длинный ответ,
ограничение параллелизма, содержимое запросов TXT/PDF/PPT/PPTX, извлечение
слайдов ODP и ошибки повреждённых/пустых ODP.

Официальные источники реализации:
[OAuth](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api),
[вложения](https://developers.sber.ru/docs/ru/gigachat/guides/working-with-files),
[сертификаты](https://developers.sber.ru/docs/ru/gigachat/certificates).
Ключи, токены и тела ошибок API не выводятся в логи.
