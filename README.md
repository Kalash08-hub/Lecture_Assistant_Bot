# Lecture Assistant Bot

Учебный Telegram-бот на Python **3.12**, aiogram **3.22.0** и GigaChat.
Один процесс/одна реплика, SQLite и ограниченная очередь без Redis и внешних сервисов очереди.

## Возможности

- Приём лекций: TXT, PDF, ODT, DOCX. Презентации: PDF, PPT, PPTX, ODP.
- Подробный конспект и краткая выжимка по всему доступному материалу.
- Тест: вопросы по очереди, один ответ на вопрос, объяснения и итоговый балл.
- Карточки: вопрос, показ ответа, переходы и повторное открытие сохранённого набора.
- «Мои лекции»: страницы по пять файлов, действия, сохранённые результаты и удаление.
- Экспорт материалов в DOCX с кириллицей; TXT — отдельная кнопка и резервный формат.
- `/start` открывает меню, `/help` начинает обращение в поддержку, `/cancel` отменяет
  диалог/скачивание и ожидающее задание. Переход в меню сохраняет лекции.
- Личные данные и материалы проверяются по владельцу при каждом обращении к записи.
  Рекомендуемый способ использования студентами — личные чаты с ботом.

Материалы создаёт ИИ: проверяйте определения, формулы и выводы по источнику.
Конспект рассчитан на подробное изложение тем и примеров, выжимка — на связный
краткий пересказ. Короткий источник не должен дополняться внешними фактами ради объёма.
Число вопросов/карточек выбирается по объёму материала (1–8 вопросов, 1–12 карточек).

## Установка и запуск

Нужен Python 3.12 с OpenSSL на Linux/macOS. Настройки проверяются до запуска polling.
Секреты и содержимое `.env` не должны попадать в Git или логи.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Команду копирования выполняйте только при отсутствии своего `.env`.
Заполните `BOT_TOKEN`, `GIGACHAT_CREDENTIALS` (ключ авторизации, без `Basic `,
не временный access token), `GIGACHAT_SCOPE` и `GIGACHAT_MODEL`.
По умолчанию scope — `GIGACHAT_API_PERS`, модель — `GigaChat-2`.
Доступность конкретной модели зависит от вашего аккаунта GigaChat.

Установите доверенный корневой сертификат по
[официальной инструкции GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates)
и задайте `GIGACHAT_CA_BUNDLE_FILE=/полный/путь/к/russian_trusted_root_ca_pem.crt`.
PEM дополняет стандартное хранилище CA Python; TLS никогда не отключается.
Путь не обязателен, если цепочка уже доверена стандартному SSL-контексту Python.
`PROXY_URL`, если нужен, относится только к Telegram; GigaChat подключается напрямую.

```sh
python -m app.main
```

Не запускайте вторую копию бота. Локальная блокировка БД защищает от случайного
повторного запуска с той же `DATABASE_PATH`.
Настройки персонального Mac вынесены в [отдельные заметки](docs/local-mac.md).

## Настройки

Полный шаблон — [.env.example](.env.example). Относительные пути считаются от корня
проекта, а не от рабочей директории запуска. Папки создаются автоматически.

| Переменная | Значение/назначение |
| --- | --- |
| `BOT_TOKEN` | Обязательный секрет Telegram |
| `AI_ENABLED` | `true`; `false` отключает новые генерации, сохраняя историю/кеш |
| `GIGACHAT_CREDENTIALS` | Обязателен при включённом ИИ |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` для личного доступа |
| `GIGACHAT_MODEL` | `GigaChat-2`, либо другая доступная модель |
| `GIGACHAT_CA_BUNDLE_FILE` | Путь к доверенному PEM |
| `PROXY_URL` | Необязательный HTTP/SOCKS-прокси Telegram |
| `ADMIN_ID` / `SUPPORT_ENABLED` | ID администратора / `true`; 0 или `false` отключает поддержку |
| `SUPPORT_COOLDOWN_SECONDS` | 300, интервал обращений; неуспешная доставка также учитывается |
| `UPLOAD_DIR` | `files` локально, `/data/uploads` на Amvera |
| `DATABASE_PATH` | `data/bot.sqlite3` локально, `/data/bot.sqlite3` на Amvera |
| `MAX_UPLOAD_BYTES` | 20971520 (20 MiB); больше нельзя для облачного Bot API |
| `MAX_USER_FILES` / `MAX_USER_BYTES` | 20 файлов / 104857600 байт на пользователя |
| `RETENTION_DAYS` | 30 дней с момента загрузки |
| `QUEUE_SIZE` / `GENERATION_WORKERS` | 10 ожидающих заданий / 1 работник |
| `DAILY_GENERATION_LIMIT` | 10 новых генераций на пользователя за сутки UTC |
| `QUEUE_TIMEOUT_SECONDS` | 300, максимальное ожидание |
| `GENERATION_TIMEOUT_SECONDS` | 240, подготовка и выполнение задания |
| `UPLOAD_TIMEOUT_SECONDS` / `HTTP_TIMEOUT_SECONDS` | 90 / 90 |
| `CLEANUP_INTERVAL_SECONDS` | 3600, обслуживание файлов и отложенных вложений |
| `ORPHAN_GRACE_SECONDS` | 3600, минимальный возраст осиротевшего файла |
| `LOG_LEVEL` | `INFO` (также DEBUG, WARNING, ERROR) |

Администратор должен начать чат с ботом, чтобы бот мог доставлять обращения.
При ошибке доставки пользователь получает подтверждение недоступности, FSM завершается;
текст обращения не сохраняется в БД и не выводится в логи.

## Форматы и ограничения

TXT читается как UTF-8 (включая BOM), с резервом Windows-1251. Из DOCX извлекаются
абзацы и текст ячеек таблиц в порядке документа; из ODT — заголовки, абзацы,
списки и текст таблиц; из ODP — текст с границами слайдов и значимыми пробелами.
**Изображения, сканы, рукописный текст и встроенные объекты формул этими локальными
обработчиками не распознаются.** Текстовые формулы сохраняются.
PDF, PPT и PPTX отправляются как вложения GigaChat; полнота их чтения зависит от модели.
Старый бинарный PPT проверяется по сигнатуре, PDF — по заголовку и признаку шифрования,
PPTX — по структуре презентации. Это практические проверки, не полный валидатор Office/PDF.

Пустые, зашифрованные или повреждённые документы отклоняются с сообщением.
Для ZIP-форматов: не более 5000 записей, 32 MiB общего распакованного объёма,
16 MiB одного XML, 2 MiB извлечённого текста, до 200000 XML-узлов и 64 уровней вложенности. XML с DTD/внешними сущностями не исполняется.
Лимит размера проверяется до скачивания, во время записи и после неё.
Большой текст может превысить контекст GigaChat: бот не обрезает источник молча,
а возвращает ошибку и предлагает разделить материал.

## Данные, очередь и кеш

Файлы сохраняются как `<UPLOAD_DIR>/<telegram_user_id>/<uuid>.<расширение>`.
SQLite хранит владельца, исходное имя, путь, формат, SHA-256, размер и срок хранения
лекции; задания со статусами/временем/категорией ошибки; результаты с моделью,
версией промпта и доступной статистикой токенов. FSM отвечает только за диалог.
После перезапуска лекции, результаты и прохождение тестов остаются в БД.

Новая загрузка не удаляет предыдущие лекции. Неудачная/отменённая загрузка удаляет
частичный файл. История позволяет удалить одну лекцию или все свои материалы;
активный или ожидающий файл защищён от удаления. Отменить можно ожидающее задание,
начатый запрос не отменяется пользователем во избежание неопределённого списания.
Истёкшие файлы удаляются при обслуживании после освобождения заданиями.
Удаление лекции удаляет связанные задания/прохождения и результаты, если они
не используются другой вашей лекцией с идентичным содержимым.

Кеш: владелец + SHA-256 + режим + модель + версия промпта. Повторный запрос готового
материала не обращается к GigaChat и не расходует дневной лимит. Кнопки старых
сохранённых лекций работают по ID и владельцу; кнопки до перехода на SQLite,
неизвестные и удалённые записи предлагают открыть историю или загрузить файл заново.
Для нового содержимого/модели/версии промпта создаётся новое задание.
Кнопки принудительной платной перегенерации пока нет.

Один пользователь может иметь только одно незавершённое задание. Очередь ограничена,
таймаут ожидания не расходует время выполнения. Отклонённые задания не занимают
место и не расходуют лимит; отменённые/прерванные до старта задания освобождают
дневной бюджет. Уже начатые попытки, включая ошибки, учитываются в лимите.
После остановки ожидающие/выполнявшиеся задания получают статус «прервано»;
**автоматически повторно не запускаются**. Запрос после неоднозначного сетевого
сбоя повторяет только сам пользователь и может потребовать новых токенов.

OAuth-токен переиспользуется с запасом до истечения срока, обновление защищено
от гонок. Ограниченные повторы выполняются для OAuth, но не для генерации/загрузки.
Удаление удалённого вложения проверяет HTTP-статус. При ошибке запись сохраняется
в БД и повторяется при обслуживании, максимум 3 попытки всего. Неудача очистки
не скрывает готовый материал. Остаточные записи после трёх неудач требуют
проверки оператором в `remote_cleanup`; локальное удаление не гарантирует удаление
на стороне провайдера при его недоступности.

Очистка сканирует только управляемые UUID-файлы в числовых каталогах пользователей;
ссылки и посторонние файлы не удаляются. Старые файлы без записи в SQLite считаются
осиротевшими после `ORPHAN_GRACE_SECONDS`. Метаданные из старой FSM не мигрируются:
перед первым обновлением сохраните нужные исходники и загрузите их заново.
Для резервного копирования согласованно сохраняйте SQLite (включая WAL при работающем
боте) и каталог загрузок; проще делать копию при остановленном процессе.

## Выдача и удаление

В каждом результате указан исходный файл. Лимит Telegram учитывается в UTF-16.
Короткий текст отправляется сообщением; для длинного материала — превью и полный
DOCX. TXT доступен отдельной кнопкой и как запасной экспорт. PDF-экспорт не реализован.
Пользователь видит краткое уведомление о передаче в GigaChat и сроке хранения
при загрузке, подробности — «Хранение и удаление данных».

## Amvera

[amvera.yaml](amvera.yaml) задаёт Python 3.12, установку requirements.txt и
`python -m app.main` по [официальной конфигурации Python/pip](https://docs.amvera.ru/applications/environments/python-pip.html).
Одна реплика, постоянный диск `/data`, переменные:

```dotenv
UPLOAD_DIR=/data/uploads
DATABASE_PATH=/data/bot.sqlite3
GIGACHAT_CA_BUNDLE_FILE=/data/certs/russian_trusted_root_ca_pem.crt
```

Разместите доверенный PEM по этому пути и задайте секреты приложения отдельно
(`BOT_TOKEN`, `GIGACHAT_CREDENTIALS`), а также модель, scope и при необходимости ADMIN_ID.
В `.env.example` нет реальных ключей. Реплики не должны совместно писать в эту БД.
Деплой, публикация и настройка аккаунта Amvera автоматически не выполняются.

## Автоматические проверки

```sh
python -m pip check
python -B -m unittest discover -s tests -v
```

GitHub Actions запускает те же проверки на Ubuntu/Python 3.12 без секретов.
Тесты используют настоящие SQLite, очередь, чтение документов и Dispatcher;
заменены только внешние Telegram/GigaChat-транспорты или генератор в тестах очереди.
Покрыты повторные нажатия, лимиты/таймауты/отмена, рестарт, ACL/кеш, поддержка,
форматы/размеры/очистка, схемы тестов и карточек, OAuth и удаление вложений, DOCX
и длинная выдача. Тесты не отправляют сообщений людям и не вызывают платный API.

Ручная проверка после настройки аккаунтов: запуск в Linux/Amvera, получение файлов
Telegram и ответы GigaChat на реальные лекции всех нужных форматов, права поддержки,
остаток токенов, цепочка CA и постоянство `/data` после перезапуска. Новый код
не объявляется проверенным вживую на основании моков.
